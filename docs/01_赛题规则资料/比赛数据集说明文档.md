# 比赛数据集说明文档

## 一、数据集概述

本数据集用于“基于不均衡小样本学习的光学遥感卫星陆上目标检测识别”比赛，仅供参赛团队在比赛期间进行模型训练、验证与测试使用。

数据集包含 **25 个细分类别**，覆盖三类目标体系：

- 舰船目标；
- 飞机目标；
- 发射车目标。

标注形式为 **YOLO 格式水平边界框**。这说明本数据集使用的是常规水平矩形框，而不是旋转框或多边形标注。

从任务角度看，训练时应按 25 个细分类别建模；从评分角度看，比赛评分方案 V1.6 仍会将细分类别聚合为舰船、飞机、车辆三个大类进行召回率、虚警率和排名参考。

## 三、类别分组说明

### 3.1 舰船类

舰船类包含 4 个细分类：

| 类别 ID | 名称 | 说明 |
| ---: | --- | --- |
| 0 | HM | 航母 |
| 1 | LQS | 两栖舰 |
| 2 | QHS | 驱护舰 |
| 3 | MS | 民船 |

舰船类内部差异较大。航母目标通常尺寸较大，民船数量和形态可能更复杂，驱护舰和两栖舰可能更容易与其他船型混淆。

训练时不能只把它们粗略当作“船”，因为 V1.6 评分方案提到船类指标会先计算四型船各自的召回率和虚警率，再取平均作为船类指标。

### 3.2 飞机类

飞机类包含 20 个细分类：

```text
A1_SU-35
A2_C-130
A3_C-17
A4_C-5
A5_F-16
A6_TU-160
A7_E-3
A8_B-52
A9_P-3C
A10_B-1B
A11_E-8
A12_TU-22
A13_F-15
A14_KC-135
A15_F-22
A16_FA-18
A17_TU-95
A18_KC-10
A19_SU-34
A20_SU-24
```

飞机类是本数据集中细分类最多的大类，也是最容易出现类别不均衡的部分。

可能存在的问题：

- 某些型号样本极少；
- 不同飞机型号外观相似；
- 同一型号在不同分辨率、角度、光照下差异明显；
- 停机坪、跑道、建筑阴影可能造成误检；
- 小型飞机或远距离飞机容易漏检。

因此，飞机类不仅要保证大类检测，还要尽量提升每个型号的稳定性。

### 3.3 车辆类

车辆类在当前数据说明中对应 1 个细分类：

| 类别 ID | 名称 | 说明 |
| ---: | --- | --- |
| 24 | FSC | 发射车 |

评分方案中称为“车辆目标”，数据说明中明确为“发射车”。在方案文档和代码配置中建议统一说明：

```text
车辆大类对应数据集中的发射车 FSC 类。
```

## 四、标注格式

标注文件为 YOLO 格式的水平边界框。

每个 `.txt` 标注文件与对应图像同名。

每行标注格式如下：

```text
类别ID x_center y_center width height
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `类别ID` | 目标所属类别，范围为 `0` 到 `24` |
| `x_center` | 目标框中心点横坐标 |
| `y_center` | 目标框中心点纵坐标 |
| `width` | 目标框宽度 |
| `height` | 目标框高度 |

其中：

- 坐标均为归一化后的浮点数；
- 坐标范围通常为 `0` 到 `1`；
- `x_center, y_center` 表示目标框中心点；
- `width, height` 表示目标框宽高；
- 标注框为水平矩形框，不包含旋转角度。

示例：

```text
8 0.512341 0.438210 0.031245 0.026781
24 0.213455 0.674322 0.018942 0.015337
```

含义：

- 第一行表示类别 ID 为 `8` 的 `A5_F-16` 目标；
- 第二行表示类别 ID 为 `24` 的 `FSC` 发射车目标。

## 五、YOLO 标注与实际像素坐标转换

YOLO 标注是归一化坐标。如果图像宽度为 `W`，高度为 `H`，则可转换为像素级水平框。

中心点和宽高：

```text
x_center_pixel = x_center * W
y_center_pixel = y_center * H
box_width_pixel = width * W
box_height_pixel = height * H
```

左上角和右下角：

```text
x1 = (x_center - width / 2) * W
y1 = (y_center - height / 2) * H
x2 = (x_center + width / 2) * W
y2 = (y_center + height / 2) * H
```

如果后续提交 COCO 检测结果，通常需要输出：

```text
[x, y, width, height]
```

这里的 `x, y` 一般表示左上角像素坐标，不是中心点坐标。

因此必须注意：

```text
YOLO: class_id x_center y_center width height，归一化中心点格式
COCO: image_id category_id bbox score，bbox 通常为像素级 [x_min, y_min, width, height]
```

这是训练标注和提交结果之间最容易出错的地方。

## 六、与评分方案 V1.6 的关系

新版评分方案 V1.6 的核心门槛仍然是：

| 指标 | 要求 |
| --- | --- |
| 整体检测召回率 | `>= 85%` |
| 虚警率/误检率 | `<= 20%` |
| 单幅 `10000 x 10000` 图像推理时间 | `<= 20 秒` |

初赛刚性指标仍然按舰船、飞机、车辆三个大类合并计算。

但 V1.6 明确补充了大类排名指标的计算方式：

- 先计算每个细分类各自的召回率和虚警率；
- 再对同一大类下的细分类指标取平均；
- 大类平均结果用于船、飞机、车辆各自的召回率和虚警率排名；
- 船、飞机、车辆各自召回率和虚警率，加上总时效性，共形成 7 个排名；
- 7 个排名的总和会参与二次排序；
- 二次排序会作为方案合理性、技术创新程度、工程可落地性打分的重要参考。

以舰船为例：

```text
船类召回率 = (HM召回率 + LQS召回率 + QHS召回率 + MS召回率) / 4
船类虚警率 = (HM虚警率 + LQS虚警率 + QHS虚警率 + MS虚警率) / 4
```

飞机类可以理解为对 20 个飞机型号分别计算后取平均。

车辆类在当前数据说明中只有 `FSC` 一个细分类，因此车辆大类指标主要由发射车检测效果决定。

## 七、对训练方案的影响

### 7.1 不能只按三个大类训练

虽然评分最终会参考舰船、飞机、车辆三个大类，但数据集提供的是 25 个细分类。

如果直接把 25 类合并成 3 类训练，可能会带来问题：

- 无法输出官方需要的细分类 ID；
- 无法统计各细分类召回率和虚警率；
- 难以满足 V1.6 中“先算细类再算大类平均”的排名逻辑；
- 飞机型号之间的差异会被模型忽略。

因此建议主模型按 25 类训练。

### 7.2 必须重视细分类不均衡

本赛题的“不均衡”不只是三大类之间不均衡，更可能体现在 25 个细分类之间。

尤其是飞机类内部，共有 20 个型号。某些型号可能样本很多，某些型号可能样本极少。

建议统计：

- 25 个类别各自目标数量；
- 25 个类别各自图像数量；
- 每类目标尺寸分布；
- 每类目标场景分布；
- 每类召回率；
- 每类虚警率；
- 每类混淆情况。

### 7.3 训练时要兼顾检测和细分类识别

模型不仅要找到目标，还要判断具体类别。

例如飞机类中，模型需要区分：

```text
SU-35、F-16、F-15、F-22、FA-18、C-130、C-17、B-52、KC-135 等型号
```

这比简单判断“飞机”更难。

因此可以考虑：

- 检测模型直接训练 25 类；
- 采用类别均衡采样；
- 对少数飞机型号进行过采样；
- 对易混淆型号做专项增强；
- 在报告中增加混淆矩阵或易混淆类别分析；
- 必要时采用二阶段方案：先检测大类目标，再对目标裁剪图进行细分类识别。

### 7.4 提交结果要注意类别 ID

训练标注的类别 ID 为 `0` 到 `24`。

最终 COCO JSON 的 `category_id` 是否也直接使用 `0` 到 `24`，需要以官方最终提交模板为准。

建议在代码中保留清晰映射：

```text
YOLO class_id -> 类别名称 -> 大类名称 -> COCO category_id
```

不要在多个脚本里重复手写类别映射，避免提交时类别错位。

## 八、数据检查建议

正式训练前建议完成以下检查：

- 图像和 `.txt` 标注文件是否一一对应；
- 是否存在空标注文件；
- 是否存在缺失标注文件；
- 类别 ID 是否都在 `0` 到 `24` 范围内；
- 坐标是否都在 `0` 到 `1` 范围内；
- `width` 和 `height` 是否大于 0；
- 标注框转换到像素坐标后是否越界；
- 是否存在极小框、异常大框、长宽比异常框；
- 每类样本数量是否严重不均衡；
- 每类目标可视化是否与类别名称一致；
- 切片后目标框是否正确映射。

## 十、推荐本地验证指标

为了贴近比赛评分，建议本地验证至少输出三层指标：

### 10.1 细分类指标

对 25 个类别分别统计：

- Recall；
- FDR；
- TP；
- FP；
- FN；
- 平均置信度；
- 漏检样例；
- 误检样例。

### 10.2 大类指标

按照 V1.6 口径聚合：

```text
舰船 = ID 0 到 3
飞机 = ID 4 到 23
车辆 = ID 24
```

分别统计：

- 舰船召回率；
- 舰船虚警率；
- 飞机召回率；
- 飞机虚警率；
- 车辆召回率；
- 车辆虚警率。

### 10.3 总体门槛指标

统计：

- 三大类合并后的整体 Recall；
- 三大类合并后的整体 FDR；
- 单幅 `10000 x 10000` 图像推理时间。

最终目标是：

```text
整体 Recall >= 85%
整体 FDR <= 20%
单幅 10000 x 10000 图像推理时间 <= 20 秒
```

## 十一、对报告写作的建议

研究报告中建议单独加入“数据集分析”章节，重点写：

- 数据集共有 25 个细分类；
- 舰船类 4 类、飞机类 20 类、车辆类 1 类；
- 标注格式为 YOLO 水平框；
- 数据存在小样本和类别不均衡问题；
- 评分会按三大类聚合，但 V1.6 会参考细分类平均后的大类指标；
- 因此方案采用 25 类检测建模，并在训练和验证中同时统计细分类与大类指标。

推荐表述：

```text
针对比赛数据集中 25 个细分类别分布不均衡的问题，本文采用类别均衡采样和少数类增强策略提升尾部类别的训练频次；同时在评估阶段分别统计 25 个细分类指标，并按照评分方案 V1.6 将舰船、飞机和车辆三大类指标进行聚合，以保证模型不仅满足整体刚性门槛，也能在细分类和大类排名中保持稳定表现。
```

## 十二、核心结论

本数据集不能简单理解为“三分类检测数据集”。

更准确的理解是：

```text
训练标注是 25 个细分类的 YOLO 水平框；
比赛门槛按舰船、飞机、车辆三大类合并计算；
V1.6 专家参考排名会先看细分类，再聚合到大类；
因此模型、评估和报告都应该同时兼顾 25 类细分识别和 3 大类综合检测。
```
