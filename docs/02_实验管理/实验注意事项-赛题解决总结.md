# 实验注意事项：赛题解决总结

## 1. 文档定位

本文档用于记录本项目后续实验、建模、数据清洗、评估和报告撰写时必须遵守的核心判断。

它不是对 `答疑.md` 的逐条复述，而是把答疑中真正会影响实验路线的信息提炼成项目执行依据。后续所有实验设计、代码实现、结果分析和研究报告，都应优先参考本文档。

一句话概括本赛题：

```text
在存在漏标、错标、小样本、类别不均衡、多源遥感图像和大图推理约束的条件下，完成 25 个细分类目标的水平框检测，并按官方规则聚合为舰船、飞机、车辆三大类进行评分。
```

## 2. 目前最重要的赛题认知

### 2.1 不能把任务理解成普通三分类检测

虽然比赛文件经常用“舰船、飞机、车辆”三个大类描述任务，但实际训练和评测都不能只按三类处理。

当前数据集是 **25 个细分类**：

- 舰船类：4 个子类；
- 飞机类：20 个子类；
- 车辆类：1 个子类，即发射车 `FSC`。

答疑中明确说明：

```text
只有子类正确分类才认定为正确。
初赛和复赛的所有指标计算，都是在子类正确分类的基础上。
```

因此，项目主线应按 **25 类检测任务**设计，而不是把所有舰船合成一类、所有飞机合成一类。

### 2.2 刚性指标仍是项目第一优先级

以评分方案 V1.6 为准，初赛刚性门槛为：

| 指标 | 要求 |
| --- | --- |
| 召回率 | `>= 85%` |
| 虚警率/误检率 | `<= 20%` |
| 单幅 `10000 x 10000` 图像推理时间 | `<= 20 秒` |

答疑中对计算口径有进一步说明：

1. 子类分类必须正确，才可能计为 TP；
2. 先分别计算舰船、飞机、车辆三个大类的召回率和虚警率；
3. 大类内部按照评分方案 V1.6 的方式由细分类指标得到；
4. 再对三个大类的召回率、虚警率分别取平均；
5. 得到最终用于刚性门槛判断的召回率和虚警率。

项目内部评估脚本必须尽量模拟这一口径。不要只输出普通 mAP，也不要只看所有框混在一起的整体准确率。

### 2.3 测试集不会告诉我们图像属于哪种目标场景

答疑明确提到，测试时只会把图片给参赛程序，不会告诉哪张是飞机、哪张是船。

这意味着：

- 不能依赖文件名、目录名、人工提示来选择模型；
- 如果使用多个模型，必须由程序自动完成场景判断或多模型融合；
- 推理入口要统一，不能手动按场景分批处理；
- 最终 Docker 或测评接口必须能从输入图像自动输出结果。

这对工程设计很关键。可以使用多个模型，但不能要求评测人员替我们选择模型。

## 3. 数据与图像层面的实验注意事项

### 3.1 图像最大尺寸是 `10000 x 10000`，不是全部固定为这个尺寸

答疑中多次说明：

- 测试图像尺寸不固定；
- 最大可能为 `10000 x 10000`；
- 测试集中只有少量图像是 `10000 x 10000`；
- 其余图像尺寸与训练集类似；
- 部分大图可能是由较小图像拼接得到。

实验影响：

- 推理代码必须支持任意尺寸图像；
- 不能写死 `10000 x 10000`；
- 切片逻辑要能处理小图、中图和大图；
- 速度测试必须包含最大尺寸压力测试；
- 本地需要自己制作若干 `10000 x 10000` 压力测试图。

推荐做法：

```text
小图：直接推理或少量切片
中图：按固定窗口重叠切片
大图：按最大压力场景做批量切片、坐标还原和跨切片融合
```

### 3.2 图像没有大气校正，也没有辐亮度信息

答疑中明确：

- 所有图像均未经过大气校正；
- 每个像素值不是辐亮度；
- 只有 DN 值；
- 训练集并不来自同一颗卫星；
- 不会提供 DN 值转辐亮度的方法；
- 后续验证集也一样。

实验影响：

- 不应把主要精力放在辐射定标、大气校正、辐亮度反演上；
- 更应该关注数据归一化、增强、域泛化和多源图像适配；
- 不同卫星、不同成像条件会带来明显域差异；
- 训练时要使用亮度、对比度、灰度扰动、噪声、模糊等增强提升鲁棒性。

推荐策略：

- 对输入做统一归一化；
- 对灰度图和彩色图分别检查通道处理；
- 增加亮度、对比度、Gamma、噪声、模糊等增强；
- 验证不同图像来源上的表现差异；
- 不做依赖具体传感器辐射参数的处理。

### 3.3 舰船图像和飞机/发射车图像存在模态差异

答疑中说明：

- 船舶测试大图是灰度图；
- 训练集中船舶是全色图或灰度图；
- 飞机和发射车是彩色图；
- 最终测试与各类别训练图像一致，即舰船灰度，飞机和发射车彩色。

实验影响：

- 模型输入必须兼容灰度和彩色图；
- 如果统一使用 3 通道输入，灰度图需要复制通道或做一致转换；
- 可以考虑训练一个统一 25 类模型，也可以考虑多模型自动融合；
- 如果多模型方案效果更好，推理程序必须自动判断或自动融合，不能人工切换。

推荐实验：

| 实验 | 目的 |
| --- | --- |
| 统一 25 类模型 | 建立最简单可复现主线 |
| 舰船灰度专用模型 + 飞机/发射车彩色模型 | 检查模态专用模型是否提升效果 |
| 自动场景分类/域判断 | 测试多模型自动切换可行性 |
| 多模型结果融合 | 在不依赖人工提示的情况下提升召回 |

## 4. 标注与数据清洗注意事项

### 4.1 训练集标注不是完全可靠的

答疑中明确承认训练集可能存在：

- 漏标；
- 错标；
- 类别混淆；
- 边界目标未标；
- 标注标准不一致。

官方给出的训练集标注主要作用是告诉参赛者要检测什么目标，不保证已经经过多轮背靠背核对。

实验影响：

- 直接使用原始标注训练，可能把真实目标当背景；
- 漏标目标会造成模型学习混乱；
- 错标会增加子类混淆；
- 小目标和边界目标尤其需要复查。

推荐做法：

1. 建立标注复核流程；
2. 优先复查少数类和高价值类别；
3. 优先复查模型高置信误检但肉眼看起来像目标的区域；
4. 建立 `label_issue` 记录表；
5. 修正后的标注单独保存，保留原始标注备份；
6. 在研究报告中说明复核方法和发现的问题。

答疑中还说明，发现训练数据集问题并在报告中明确指出，可以作为团队工作的亮点。

### 4.2 测试集标注会更严格

答疑中说明测试集会由专业标注人员多重标注和核对。

测试集原则：

- 所有目视能分辨的目标都需要检测；
- 边缘出镜目标会被标注；
- 测试集不会故意保留“骑边但未标注”的目标；
- 肉眼无法分辨的发射车目标不会作为得分依据；
- 轮廓已经看不清的小目标可以不作为标注对象。

实验影响：

- 训练集中漏标的目标，不能简单当作负样本；
- 在测试集中检测出清晰目标不会因为官方漏标而吃亏的可能性更低；
- 本地验证集最好也按“目视可辨即标注”的标准修正；
- 边界目标、半出镜目标应纳入训练和评估。

### 4.3 边界目标和半出镜目标必须重视

答疑明确：

```text
只有一半出镜的目标也应该被识别。
测试数据中这些都会被标注。
```

实验影响：

- 切片训练时不能简单丢弃所有被切断的目标；
- 推理切片必须有重叠区域；
- 后处理要避免把边界半框误删；
- 本地验证集中要检查骑边目标的召回。

推荐策略：

- 训练切片时保留可辨认的边界目标；
- 对切片边缘目标设置合理保留比例；
- 推理切片使用 `20%` 到 `30%` 重叠；
- 对跨切片重复框做 NMS 或 WBF；
- 单独统计边界目标召回率。

### 4.4 舰船标注标准要按“可辨轮廓”和“四类规则”处理

答疑中关于舰船有几个关键规则：

- 不属于航母、两栖舰、驱护舰的船只，都标注为民船；
- 无法判定具体型号的船只，按民船处理；
- 能看清轮廓的船只需要标注；
- 目视已经看不清轮廓的小目标可以不用标注；
- 大型民船旁边贴着的小船，如果能分辨，应作为单独目标；
- 民船小目标标准不是按尺寸硬切，而是按是否能看清轮廓判断；
- 舰船类别标准可以参考遥感舰船数据集，例如 HRSC-2016。

实验影响：

- 船类不是只标大船；
- 小船漏标会影响训练；
- 民船类可能非常复杂，是虚警和漏检的重灾区；
- QHS、LQS 等军舰细类容易混淆，需要重点复查。

推荐策略：

- 建立舰船复核规则表；
- 对航母、两栖舰、驱护舰、民船各自收集代表样例；
- 对不确定军舰类别建立人工复核池；
- 对不确定但可见的普通船，优先标为民船；
- 对密集小船港口区域做专项验证。

### 4.5 发射车只检测发射车，不检测普通车辆

答疑明确：

- 车辆大类只包含发射车；
- 测试集里的车是发射车；
- 普通卡车、货车、民用车辆不属于目标；
- 单独车头、单独货物、车头加货物整体都可能算发射车；
- 但目标应具有明显发射车特征；
- 低分辨率下肉眼无法分辨是否为发射车的车辆，测试集不会作为得分依据。

实验影响：

- 不能把普通车辆数据随意加入发射车训练；
- 外部数据中如果包含普通军车或卡车，要严格筛选；
- 发射车与普通货车的混淆是潜在虚警来源；
- 训练时应加入普通车辆作为困难负样本，而不是正样本。

推荐策略：

- 单独建立发射车正样本库；
- 建立普通卡车/货车困难负样本库；
- 对模糊不可辨目标设置忽略或低权重；
- 在报告中说明发射车判定标准。

## 5. 外部数据使用策略

答疑明确允许使用外部数据：

```text
训练数据不做约束，可以引入外部数据。
只要不把测试集纳入训练，并在报告中描述清楚使用的数据集，且可以复现即可。
```

实验影响：

- 可以使用公开遥感舰船、飞机、车辆数据集；
- 可以使用相似目标数据做预训练或增广；
- 可以使用外部背景负样本降低虚警；
- 但必须记录来源、类别映射、处理流程和使用方式。

需要注意：

- 外部数据的类别定义可能与官方 25 类不一致；
- 外部旋转框数据要转换为水平框；
- 外部 RGB 数据与本赛题灰度舰船图存在域差异；
- 不要引入与官方测试集重合的数据；
- 报告中必须保证可复现。

推荐使用方式：

| 用法 | 说明 |
| --- | --- |
| 预训练 | 用外部相似数据提升基础检测能力 |
| 少数类补充 | 对样本极少的飞机型号、舰船类型补充相似样本 |
| Copy-Paste 实例库 | 裁剪外部目标实例用于增强 |
| 困难负样本 | 加入港口、机场、道路、普通车辆等背景 |
| 半监督伪标签 | 对未标注或外部图像生成伪标签后筛选 |

## 6. 模型与推理策略

### 6.1 允许使用多模型和复杂后处理

答疑明确允许：

- 多个模型；
- 多个权重；
- 自动融合；
- WBF；
- Soft-NMS；
- 多模型投票；
- TTA；
- 重叠切片；
- 批量推理；
- 坐标还原；
- 跨切片结果融合；
- FP16；
- ONNX；
- TensorRT。

这给了我们比较大的工程自由度。

但需要注意：

- 多模型会增加推理时间；
- TTA 会明显增加耗时；
- WBF 和跨切片融合如果实现不好，会产生重复框；
- 最终仍要满足单幅大图 20 秒内推理。

推荐策略：

1. 先用单模型跑通完整流程；
2. 再尝试多模型或专用模型；
3. 每次加复杂策略都记录精度收益和耗时成本；
4. 对最终方案做速度压力测试；
5. 如果复杂融合提升有限，应优先选择更稳定、更快的方案。

### 6.2 官方不会自动合并重复框

答疑明确：

```text
官方测评时不会自动合并重复框。
```

这意味着重复检测框会计为 FP，直接增加虚警率。

实验影响：

- 跨切片重复框必须由我们自己处理；
- 同一目标多个预测框，只能最高置信度框计为 TP，其余计为 FP；
- NMS、Soft-NMS、WBF 参数非常重要；
- 提高召回时不能让重复框失控。

推荐检查：

- 可视化密集场景预测框；
- 统计每个 GT 周围重复框数量；
- 分类别调 NMS；
- 对大图跨切片结果做全局 NMS；
- 建立重复框误检案例集。

### 6.3 置信度阈值由参赛团队自行决定

答疑说明对置信度阈值没有官方固定要求。

实验影响：

- 阈值是召回率和虚警率平衡的核心参数；
- 可以使用统一阈值，也可以使用分类别阈值；
- 少数类可能需要较低阈值；
- 高虚警类别可能需要较高阈值。

推荐实验：

- 搜索全局 score 阈值；
- 搜索 25 个细分类阈值；
- 搜索三大类阈值；
- 同时记录 Recall、FDR、TP、FP、FN；
- 以刚性指标为第一约束，再优化排名。

## 7. 本地验证必须比官方反馈更细

答疑中提到，测试反馈暂定到大类指标，不一定会给小类的召回率和虚警率。

这意味着如果只依赖官方反馈，很难知道是哪一个子类拖后腿。

项目内部必须建立更细的验证体系：

### 7.1 细分类验证

对 25 类分别统计：

- Recall；
- FDR；
- TP；
- FP；
- FN；
- 平均置信度；
- 重复框数量；
- 漏检可视化；
- 误检可视化；
- 混淆类别。

### 7.2 大类验证

按评分口径统计：

- 舰船 Recall/FDR；
- 飞机 Recall/FDR；
- 发射车 Recall/FDR；
- 三大类平均 Recall；
- 三大类平均 FDR。

### 7.3 场景验证

按场景统计：

- 灰度舰船图；
- 彩色飞机图；
- 彩色发射车图；
- 小图；
- 大图；
- 拼接大图；
- 港口密集小船；
- 机场密集飞机；
- 边界目标；
- 模糊目标。

## 8. 推荐实验主线

### 8.1 第一阶段：建立可信基线

目标：

```text
完成 25 类检测闭环，能训练、推理、评估、可视化、生成提交格式。
```

必须完成：

- 数据读取；
- YOLO 标注解析；
- 类别映射检查；
- 原图可视化；
- 训练/验证划分；
- 基线模型训练；
- 推理结果坐标还原；
- COCO/提交格式转换；
- 本地 Recall/FDR 评估；
- 可视化误检和漏检。

### 8.2 第二阶段：修数据和补标

目标：

```text
减少训练集漏标、错标对模型的干扰。
```

重点：

- 舰船小目标；
- 边界目标；
- 民船漏标；
- QHS/LQS/HM/MS 混淆；
- 发射车与普通车辆混淆；
- 飞机型号混淆；
- 标注框过大、过小、越界。

数据清洗结果要形成记录，后续写进报告。

### 8.3 第三阶段：提升召回率

目标：

```text
三大类平均 Recall 达到 85% 以上。
```

可尝试：

- 更高输入分辨率；
- 重叠切片；
- 小目标增强；
- 类别均衡采样；
- 少数类过采样；
- Copy-Paste；
- 外部数据预训练；
- 降低阈值；
- 多尺度训练。

### 8.4 第四阶段：压低虚警率

目标：

```text
在 Recall 达标的前提下，将 FDR 控制到 20% 以下。
```

可尝试：

- 困难负样本；
- 普通船/普通车/建筑物背景负样本；
- 分类别阈值；
- 全局 NMS；
- 跨切片融合；
- 异常尺寸过滤；
- 重复框清理；
- 错误案例再训练。

### 8.5 第五阶段：速度和封装

目标：

```text
最大 10000 x 10000 图像推理时间不超过 20 秒，并能通过统一接口自动处理所有图像。
```

可尝试：

- 批量切片推理；
- FP16；
- ONNX；
- TensorRT；
- 减少 TTA；
- 控制重叠率；
- 快速 NMS；
- 多模型按需加载或常驻加载；
- Docker 封装。

## 9. 关键风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 把任务当三分类 | 子类错误导致 TP 不成立 | 全流程按 25 类处理 |
| 训练集漏标 | 真实目标被当背景，召回下降 | 复核标注、修正标签、报告说明 |
| 边界目标处理不当 | 半出镜目标漏检 | 切片保留边界目标，推理重叠 |
| 重复框过多 | FP 增加，FDR 超标 | 全局 NMS/WBF，重复框统计 |
| 外部数据类别不一致 | 引入噪声 | 明确映射和筛选规则 |
| 灰度/彩色域差异 | 舰船或飞机性能不稳定 | 分模态增强或专用模型 |
| 多模型过慢 | 超过 20 秒 | 记录精度收益和耗时成本 |
| 发射车与普通车混淆 | 虚警增加 | 普通车辆作为困难负样本 |
| 小船和民船漏标 | 船类召回下降 | 按可辨轮廓复核和补标 |
| 官方反馈不够细 | 难定位问题 | 本地输出 25 类详细指标 |

## 11. 项目执行结论

后续项目启动时，建议把本文档作为实验根基。

最稳妥的主线是：

```text
25 类水平框检测
+ 自修训练标注
+ 重叠切片大图推理
+ 子类正确评估
+ 三大类聚合指标
+ 困难负样本降虚警
+ 少数类增强提召回
+ 自动化多模型/单模型推理接口
+ 速度压力测试
```

真正决定结果的不是单个模型名字，而是：

1. 数据清洗是否扎实；
2. 子类分类是否正确；
3. 切片和重复框处理是否可靠；
4. 召回和虚警阈值是否调好；
5. 大图推理速度是否可控；
6. 报告能否把数据问题、解决策略和实验结果讲清楚。
