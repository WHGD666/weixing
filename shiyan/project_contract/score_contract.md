# 在线测评评分公式

状态：**已根据官方更新公示和历史官方结果校验**

## 1. 公式

设：

- `r`：用于线上评分的三大类平均 Recall；
- `f`：用于线上评分的三大类平均 False Detection Rate；
- `t`：总时效性，单位为秒。

官方更新公示给出的三个分项得分为：

```text
Sr = r / 0.85 * 60                         , 0 <= r <= 0.85
     60 + (r - 0.85) / 0.15 * 40            , 0.85 < r <= 1

Sf = 100 - f / 0.2 * 40                    , 0 <= f <= 0.2
     60 - (f - 0.2) / 0.8 * 60              , 0.2 < f <= 1

St = 100 - t / 20 * 40                     , 0 <= t <= 20
     0                                      , t > 20

总分 = (Sr + Sf + St) / 3
```

边界含义：`r=0.85` 得 60 分，`f=0.20` 得 60 分，`t=20` 得 60 分；推理时间超过 20 秒时，时效性分为 0。

## 2. r、f 的项目口径

比赛答疑明确：

- 子类必须正确分类才算正确；
- 刚性指标的 Recall/FDR 先得到舰船、飞机、车辆三个大类指标，再对三个大类分别取平均；
- 基础性能指标不是对报告中的子类指标简单混用。

当前项目将线上评分复现中的 `r`、`f` 实现为 `evaluate_official.py` 输出的 `group_mean.recall` 和 `group_mean.fdr`，并把三大类明细和 pooled overall 同时保留。这样既能执行刚性 gate，也能复现线上分数。对本地固定小图验证，`t` 只能使用逐图平均耗时作内部估计；它不能替代平台在大图测试中报告的 `average_inference_time_sec`。

## 3. 与历史官方成绩校验

## 4. 第一次正式提交暴露的计分差异

第一次正式提交 `FORMAL001` / `3496` 的页面可见指标为：三大类宏平均 Recall `0.844112`、宏平均 FDR `0.227895333`、平均推理时间 `1.7846s`，平台显示综合分 `70.5805`。

把这些页面可见值代入第 1 节公式得到约 `71.3077`，与平台值相差约 `0.7272`，该差异无法由页面六位小数的普通舍入解释。因此，第 1 节公式目前只能视为对两次历史试运行的已验证复现，不能在缺少官方说明时宣称能够精确复现正式提交分数。

可能原因包括平台使用未展示的更细粒度值、不同聚合口径或后续更新公式；当前没有证据选择其中任何一种。正式结果以平台 `70.5805` 为准，差异保留为待官方确认项。完整记录见 `shiyan/submissions/official_feedback/FORMAL001_v1_3496.md`。

刚性指标口径也存在版本冲突：评分方案 V1.6 第 2 节写“三类目标合并计算”，2026-09-01 后续官方答疑则明确回答按舰船、飞机、车辆三大类算术平均。项目暂按时间更晚的答疑执行，但在主办方书面确认前不得隐去该冲突。

## 5. 与旧记录的关系

项目早期文档记录了“性能基础分 70 + 方案/创新/工程各 10”的作品总评结构，但没有写出线上测评三个指标的分段公式。当前公示公式补充并明确了线上测评分数的连续计算方式；它没有改变 `Recall>=0.85`、`FDR<=0.20`、`time<=20s` 三个刚性阈值。

因此后续报告必须区分：

1. 线上 Docker 测评综合分：使用本文件公式；
2. 初赛/决赛的方案、创新、工程等专家评审项：按官方最终评分文件和通知执行；
3. 本地评估：标明是公开固定验证集的内部复现，不冒充隐藏测试成绩。

## 6. 对数据审计和训练的影响

这次公式确认了优化优先级：

- `r` 在 0.85 以上时，每提升 Recall 仍直接提高分数；
- `f` 在 0.20 以下后，继续降低 FDR 仍有收益，但收益斜率不同；
- `t` 已远低于 20 秒，不应为了速度牺牲检测质量；
- 当前 v2 的主要提升空间仍是车辆/FSC 和舰船/MS 的真实检测质量，而不是继续盲调阈值。

数据审计必须优先遵守官方答疑：可辨认目标应标注，半出镜目标应标注，贴着的大船小船算两个，无法判定船型的船按民船处理；肉眼无法辨认的发射车不作为得分依据。原始 `v0_original` 标签保持只读，确认问题后再建立新标签版本。
