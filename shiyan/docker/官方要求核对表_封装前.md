本文只作为封装前的约束清单，依据本目录中的官方 Docker 封装说明、官方 Dockerfile、评测管理系统手册和答疑记录整理。若官方页面或后续答疑更新，以最新官方要求为准。

## 一、不可改变的交付结构

```text
detector-docker-delivery/
├── Dockerfile
├── environment.yml
├── app/
│   ├── main.py
│   ├── detector.py
│   ├── preprocess.py
│   ├── postprocess.py
│   └── 其他推理代码
└── models/
    └── 推理模型文件
```

核对要求：

- `Dockerfile` 以比赛方提供版本为准，除非确有必要，不自行改基础镜像和入口机制。
- `app/` 放入口、推理、预处理、后处理、类别表和配置。
- `models/` 放模型权重，代码使用容器内 `/app/models/` 路径。
- 不把数据集、训练缓存、Windows 路径和无关实验产物放进交付目录。

当前状态：官方 `Dockerfile` 已在 `shiyan/docker/`，并已复制到 `submit/v1/Dockerfile`；`submit/v1/app/`、本地模型构建上下文和 Linux `environment.yml` 已整理；`submit/v1` 已完成 GPU、断网和 897 张全量 Docker 验证。

## 二、环境要求

- 基础镜像：官方模板指定的 CUDA 12.1.1、Ubuntu 22.04。
- 环境管理器：Dockerfile 内使用 micromamba。
- `environment.yml`：必须在 Linux x86_64 环境中由实际依赖环境导出，不能直接使用 Windows conda 导出结果。
- PyTorch、Ultralytics、OpenCV 等依赖必须与 CUDA 12.1 兼容。
- 镜像运行时不能联网，模型和依赖不能在启动时下载。

关键澄清：用 Conda 在 Linux 中生成 `environment.yml`，再由 Dockerfile 中的 micromamba 读取并创建环境，不构成冲突。

当前状态：Windows 本机研发环境已验证；`submit/v1/environment.yml` 已在 Docker 构建中实际使用，并通过容器启动、GPU 推理和断网运行验证。

## 三、入口和 GPU 要求

容器启动命令必须支持：

```bash
python /app/main.py --input /input --output /output
```

`main.py` 必须完成：

1. 启动时检查 GPU 是否可用；官方模板要求保留 `check_gpu()` 或实现等价检查。
2. 只读取 `/input` 第一层的 `.jpg`、`.jpeg`、`.png`、`.bmp` 图片。
3. 模型只加载一次，不能对每张图重复初始化。
4. 实际推理使用 GPU，而不是只安装 CUDA 版框架。
5. 支持官方传入的 `--input` 和 `--output` 参数。
6. 推理完成后写出 `/output/result.json`。

当前状态：`submit/v1/app/main.py` 已支持官方输入输出参数，已实现 GPU 启动检查、模型单次加载、第一层图片读取和结果写出；Docker 容器全量验证已通过。

## 四、结果文件要求

文件位置固定为：

```text
/output/result.json
```

顶层结构必须包含：

```json
{
  "status": "success",
  "images": []
}
```

每张输入图片都必须有一条结果，即使没有检测目标也要保留空的 `objects`：

```json
{
  "image_id": "图片文件名stem",
  "file_name": "原始文件名.jpg",
  "width": 1920,
  "height": 1080,
  "run_end_timestamp": 1723968000123,
  "objects": []
}
```

每个目标必须包含：

```json
{
  "category_id": 0,
  "category_name": "HM",
  "score": 0.9321,
  "bbox": [100.5, 200.0, 500.0, 700.0]
}
```

绝对要求：

- `category_id` 是整数，使用比赛规定的 25 类编号。
- `category_name` 与类别 ID 一一对应。
- `score` 在 0 到 1 之间。
- `bbox` 是原图像素坐标 `[x1, y1, x2, y2]`。
- `bbox` 不是 YOLO 归一化坐标，也不是 COCO `[x, y, width, height]`。
- `run_end_timestamp` 必须在该图片推理结束后立即记录 Unix 毫秒时间戳。
- `images` 必须覆盖 `/input` 中全部合法图片，不能漏图或重复。

当前状态：内部 `result.json` 生成器和严格校验已通过本地测试；Docker 入口已完成 897 张全量运行并通过内部指标核验。

## 五、10,000×10,000 图像要求

- 官方性能要求针对单张 10,000×10,000 像素图像。
- 不能依赖整图直接送入模型，必须使用切片、重叠区域合并和跨切片去重。
- 当前 tiled 路径已经完成 12 张冒烟和 897 张验证集全量推理。
- 实验脚本全量切片测试最大单图耗时为 `3.538s`；提交入口全量集成测试最大单图耗时为 `5.049s`。
- 测试图尺寸与官方封闭大图可能不同，以上数据不能直接等同于官方成绩。

## 六、构建与本地运行核对

必须在 Linux x86_64、WSL2 或等价环境中完成：

```bash
docker build --platform linux/amd64 -t detector-team001:1.0 .
docker image inspect detector-team001:1.0 --format '{{.Architecture}}|{{.Os}}'
```

结果必须是：

```text
amd64|linux
```

本地运行必须模拟评测环境：

```bash
docker run --rm \
  --gpus '"device=0"' \
  --network none \
  -v "$PWD/test-input:/input:ro" \
  -v "$PWD/test-output:/output" \
  detector-team001:1.0 \
  --input /input \
  --output /output
```

验证内容：

- 容器能够启动并通过 GPU 检查；
- 容器断网后仍能完成推理；
- `/output/result.json` 正常生成；
- 至少使用一张真实比赛格式图片；
- 文件字段、图片覆盖率、类别编号和 bbox 坐标全部正确；
- 模型加载不依赖网络。
