# experiments

多轮实验管理目录。这里记录实验事实，不只记录成功结果。

当前统一状态入口：[`PROJECT_STATUS_20260904.md`](PROJECT_STATUS_20260904.md)。

目录：

- `registry/`：实验总表和 run 总表。
- `run_manifests/`：每次正式 run 的不可变 manifest。
- `comparisons/`：同一协议下可比较实验的对比表。
- `failures/`：失败实验、异常、拒绝原因。
- `notes/`：阶段性实验复盘。
- `evidence/`：供实验报告使用的少量训练曲线、预测示例和错误分析图片。

## run_id 建议

```text
YYYYMMDD_HHMM_task_experiment_shortid
```

示例：

```text
20260826_0100_det25_baseline_yolo_v0
```

## 实验收尾硬约束

每个实验、测试或阶段任务结束后，必须完成一次收尾记录，不能只保留模型文件和终端输出。收尾记录至少包含：

- 实验目标、实际执行内容和是否按计划完成。
- 数据、标签、划分、模型、推理和评估配置，以及对应 Git commit。
- 机器可读指标、样本数量、耗时、产物路径和文件哈希。
- 误检、漏检、异常、失败原因和数据质量问题。
- 对结果的解释、是否可以和其他实验直接比较、是否能写入研究报告。
- 明确结论、当前决策和下一步动作。

只有完成上述记录并检查产物后，实验才算真正结束。失败或被拒绝的实验也必须保留记录，不得删除后重新开始编号。
