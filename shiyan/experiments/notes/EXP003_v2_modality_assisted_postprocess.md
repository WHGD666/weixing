# EXP003：v2 图像模态辅助后处理实验记录

状态：**diagnostic_completed，已暂停后续执行，未提交官方平台**

本实验验证一个来自数据观察的假设：三大类中，船只图像主要或全部为黑白图，飞机和导弹车图像为彩色图。实验不改标签、不训练模型、不修改 `submit/v2`，只调用当前 v2 检测器，在模型输出后根据整张图片的黑白/彩色特征调整船只置信度阈值。

## 1. 版本关系与判断依据

为避免再次混淆，本项目当前使用以下名称：

| 标识 | 含义 | 用途 |
| --- | --- | --- |
| `trial-v2.0` | 测试提交中的最高分版本 | 仅作历史开发参考，不作为正式判断依据 |
| `v1.0` / submission `3496` | 正式提交的 v2 版本 | 正式基线，得分 `70.5805` |
| `v2.0` / submission `3720` | 使用人工修订数据训练的 v3 版本 | 正式失败结果，得分 `58.0075` |
| `submit/v2/models/best.pt` | 本次模态实验使用的 v2 模型权重 | 仅作为固定检测模型，不以测试提交得分证明有效 |

后续模型选择优先看三项刚性指标：三大类宏平均 Recall、三大类宏平均 FDR 和推理时间。平台综合分只保存为参考信息，不作为本实验的主要选择标准。

## 2. 实验假设

用户对数据集进行全量观察后提出：

- 船只类别的图像为黑白图；
- 飞机和导弹车类别的图像为彩色图；
- 数据集可能由大图切割为小图，因此船只或飞机被切掉船头、船尾或机身的一部分，未必是错误标签；
- 黑白/彩色差异可能是传感器或数据来源差异形成的强域特征。

该假设可能帮助模型区分三大类，但它不是目标类别的本质定义。黑白/彩色只应作为软先验，不能直接规定“彩色图绝不可能有船”或删除所有看起来不完整的目标。

## 3. 实验实现

代码：`shiyan/scripts/run_v2_modality_experiment.py`。

检测器来源：`submit/v2/app/detector.py`。模型、tiled 参数和类别顺序均沿用 v2；本实验只在检测结果生成后执行图像模态判定和类别阈值过滤。

模态判定规则：读取整张图的 BGR 三通道，计算通道最大值与最小值的差异。默认判定为黑白图的条件为：

```text
mean_channel_range <= 0.02
colored_pixel_fraction <= 0.05
```

soft 策略：

```text
模型预过滤 conf       = 0.10
黑白图船只阈值        = 0.20
彩色图船只阈值        = 0.60
飞机阈值              = 0.30
导弹车/FSC 阈值       = 0.35
```

control 策略使用相同的模型预过滤 `conf=0.10`，但船只在黑白和彩色图均使用 `0.30`，不产生模态差异。这样可以把 `conf=0.10` 的影响与颜色策略区分开。

## 4. 全量模态统计

固定验证清单：`v1_scene_80_20`，共 897 张图。

```text
grayscale_images = 266
color_images     = 631
```

抽样 smoke 的 4 张黑白图通道差异均为 `0.0`，说明当前判定规则能够识别明显的灰度图；这只是流程验证，不代表隐藏测试分布。

## 5. 全量结果：control 与 soft

两次实验均使用同一 v2 权重、同一 897 张验证图、同一 tiled 参数和同一评估脚本。

### 5.1 三大类指标

| 指标 | control | soft | soft - control |
| --- | ---: | ---: | ---: |
| ship Recall | 0.832700 | 0.847909 | +0.015209 |
| ship FDR | 0.200730 | 0.262810 | +0.062080 |
| aircraft Recall | 0.987899 | 0.987899 | 0 |
| aircraft FDR | 0.044681 | 0.044681 | 0 |
| vehicle Recall | 0.827160 | 0.827160 | 0 |
| vehicle FDR | 0.330000 | 0.330000 | 0 |
| 宏平均 Recall | 0.882586 | 0.887656 | +0.005070 |
| 宏平均 FDR | 0.191804 | 0.212497 | +0.020693 |
| 最大单图耗时 | 6.121 s | 4.575 s | 不作性能归因 |

control 的 TP/FP/FN 为 `4097/311/146`，soft 的 TP/FP/FN 为 `4105/360/138`。

soft 使船只多匹配 8 个目标、少漏检 8 个目标，但同时增加 49 个误检。飞机和导弹车结果不变，说明本次变化主要来自黑白图上的船只低阈值。

### 5.2 刚性指标判断

control：

```text
宏平均 Recall = 0.882586，达到 0.85
宏平均 FDR    = 0.191804，达到 0.20
推理时间      = 通过
```

soft：

```text
宏平均 Recall = 0.887656，达到 0.85
宏平均 FDR    = 0.212497，未达到 0.20
推理时间      = 通过
```

因此 soft 版本不能作为提交候选。它证明颜色信息对船只 Recall 有一定可利用信号，但当前阈值力度过大，不能满足三项刚性指标。

### 5.3 gray027 候选

在相同 v2 权重、固定验证集和推理流程下，进一步测试黑白图船只阈值 `0.27`、彩色图船只阈值 `0.60`，飞机阈值 `0.30`、FSC 阈值 `0.35`。该版本的官方口径复现结果为：

| 指标 | gray027 |
| --- | ---: |
| ship Recall | 0.8346007605 |
| ship FDR | 0.2216312057 |
| aircraft Recall | 0.9878987899 |
| aircraft FDR | 0.0446808511 |
| vehicle Recall | 0.8271604938 |
| vehicle FDR | 0.3300000000 |
| 宏平均 Recall | 0.8832200147 |
| 宏平均 FDR | 0.1987706856 |
| 最大单图耗时 | 5.190938 s |

gray027 在本地三项 gate 上通过，且比 `0.20` 阈值的 soft 版本明显降低了宏平均 FDR；但船只 Recall 仍低于 `0.85`，其通过主要依靠飞机和 vehicle 的分组表现。它是当前颜色策略的可复测候选，不是隐藏测试保证，更不能直接等同正式提交结果。

## 6. 本实验能说明什么

可以确认的内容：

1. `conf=0.10` 本身不是主要问题，因为相同预过滤设置下 control 仍通过本地三项 gate。
2. 黑白图降低船只阈值确实提高了本地船只 Recall。
3. 当前 `ship-gray-conf=0.20` 带来的误检代价明显大于召回收益。
4. 模态策略在本次实现中没有影响飞机和导弹车指标。
5. 颜色规律适合作为软先验或阈值校准依据，不适合作为硬类别过滤规则。

不能确认的内容：

1. 不能用本地 897 张图证明隐藏测试一定提升。
2. 不能用 `trial-v2.0` 的测试高分证明模态策略有效。
3. 不能说明 v3 正式提交下降完全由标签修改造成。
4. 不能据此删除彩色图里的船只预测或删除被切割的有效目标。

## 7. 与正式结果的联系

正式提交 `3720 / v2.0` 的隐藏测试结果为：ship Recall `0.284132`、aircraft Recall `0.901458`、vehicle Recall `0.705263`，三类宏平均 Recall `0.630284`；ship FDR `0.174486`、aircraft FDR `0.182432`、vehicle FDR `0.524823`，三类宏平均 FDR `0.293914`。正式结果说明当前候选在船只召回和导弹车虚警方面存在严重风险。

本地 control/soft 的指标不能替代隐藏测试。此前本地验证接近通过而正式结果未通过，已经证明验证集存在分布差异。因此后续本地候选必须留出比门槛更大的安全余量，不能以 `0.85` 或 `0.20` 附近的勉强通过作为上传理由。

## 8. 其他优先级建议

### 8.1 第一优先：模态策略做小范围阈值扫描

保持 v2 权重、数据和推理参数不变，只测试黑白图船只阈值 `0.25`、`0.28`、`0.30`，彩色图船只阈值暂时保持 `0.60`。选择条件不是分数，而是三项指标同时通过，并且宏平均 FDR 留有余量。

当前 soft 的 `0.20` 不再继续下探，也暂不采用彩色图完全删除船只的 strict 方案。

### 8.2 第二优先：导弹车/FSC 专项分析

本地 vehicle FDR 已为 `0.33`，正式隐藏测试为 `0.524823`，这是比当前颜色策略更危险的方向。后续应单独检查 FSC 的误检来源、阈值与 Recall 的交换关系，不能只靠提高阈值，因为 vehicle Recall 同时偏低。

### 8.3 第三优先：恢复被误删的切割目标

数据很可能由大图切割得到。只要船头、船尾、机身残片仍能确认属于目标，标注框应覆盖图中可见部分；不能要求目标必须完整，也不能因为目标碰到图像边缘就删除。只删除纯背景、无法确认的噪声框或确实错误的类别。

这项审查应优先覆盖人工修改过的前 1360 张，尤其是被删除或缩小过的 ship/MS/QHS/FSC 框，不需要从头重标 4481 张。

### 8.4 第四优先：修正训练初始化后再训练

EXP002 中 `pretrained:false` 导致实际从头训练。下一次比较原始标签和人工修订标签时，必须固定初始化方式，正确使用 v2 checkpoint 微调，避免把标签效果、初始化方式和训练轮数混在一起。

### 8.5 第五优先：分模态、分来源验证

除总体三大类指标外，还应分别统计黑白/彩色图、场景来源和边界截断目标的 Recall/FDR。若全量图像尺寸都小于 `1024`，推理时的 tile overlap 对已经发生在数据制作阶段的切割问题不会产生帮助，不能把两类切割混为一谈。

## 9. 暂停与冻结决定

- 本实验只完成诊断，不上传任何新镜像，不提交官方平台。
- `submit/v2/models/best.pt` 继续作为本轮后处理研究的固定模型。
- v3 及人工修订训练结果继续冻结，不作为当前默认候选。
- soft 当前结果记录为“Recall 有收益、FDR 不合格”的负向候选。
- 下一步先由项目成员决定是否执行阈值扫描；在此之前不改代码、不改标签、不训练。
- 最终报告应把本实验作为“模态先验得到初步支持，但软阈值过低导致虚警超标”的探索性实验。
