## 1. 目标

在不重新训练、不覆盖既有权重、不提交平台的前提下，同时验证原始模型、原始数据续训模型和 data3 人工修订模型。每个候选必须分别按 D0 原始标签和 D3 人工修订标签评分，最终以两套协议中的最差三大类宏平均 Recall/FDR 作为稳健性参考。

刚性指标：

- 三大类宏平均 Recall `>=0.85`

考虑已观测到的本地到平台分布偏移，本地目标安全线为 Recall `>=0.90`、FDR 尽量 `<=0.10-0.12`。

## 4. 实现

- `validate_label_protocol_mapping.py`：验证图像映射、图像哈希及标签语义变化。
- `cache_multi_model_predictions.py`：按模型顺序推理并释放显存，生成 `multi_model_cache_v1`。
- `run_multimodel_postprocess.py`：支持模型子集、大类路由、union、consensus、二票/三票 vote、模态约束和组内 NMS。
- `evaluate_two_label_protocols.py`：同一预测自动完成 D0/D3 两套评分并输出最差口径硬门槛。
- `sweep_group_thresholds.py`：一次加载 D0/D3 标签，扫描共识框、单模型框、三大组及指定细分类阈值，输出双协议最差指标与 Pareto 前沿。
- `append_model_views_to_cache.py`：在既有缓存上追加同一冻结模型的不同尺度或水平翻转视角，避免重复计算已有 1024 结果。
- `algorithmic_postprocess.py`：纯 Python 多模型聚类与后处理核心。

多模型聚类保证一个模型在同一目标簇中最多贡献一票。类别冲突时优先使用声明的大类来源；没有优先来源时按类别置信度总和选择。船只大小不作为硬过滤条件。

## 5. 实验顺序

1. 缓存 A/B/C 在 D0 验证图上的低阈值预测，global conf 固定为 `0.05`。
2. 分别复现 A、B、C 单模型 control，并对每份结果执行 D0/D3 双口径评分。
3. 单独测试组内 NMS、双向模态约束和 A/A/B、A/A/C 等大类路由。
4. 测试 A+B、A+C、B+C 两模型 consensus。
5. 测试 A+B+C 二票一致性；三票一致性只作为 FDR 下界诊断。
6. 只有前述因素单独有效后才组合，不用 12 张 smoke 选择候选。
7. 最优两组才进入 TTA、Docker 全量验收和提交候选冻结。

## 7. 第一阶段算法搜索结果

### 7.1 已排除或降级的路线

| 因素 | 最差 Recall | 最差 FDR | 判断 |
| --- | ---: | ---: | --- |
| A + 组内 NMS 0.50 | 0.879860 | 0.189607 | FDR 改善过小且损失 Recall |
| A + strict 模态过滤 | 0.881119 | 0.191782 | 颜色/灰度只提供极小保险，不是主增益来源 |
| A+B 低阈值 consensus | 0.886389 | 0.230314 | 低阈值共同虚警被放大，FDR 失败 |
| A+B+C 二票，校准阈值 | 0.883846 | 0.224721 | 三模型虚警高度相关，简单投票失败 |
| A+B+C consensus mean | 0.885205 | 0.215319 | FDR 失败 |
| A+B+C 类别投票 | 0.886381 | 0.234655 | C 增加相关虚警，失败 |

结论：颜色规则、简单 NMS 和“模型越多越好”的投票都不能解释平台差距。当前有效因素是按大类选模型、提高车辆阈值、重叠框类别投票以及对 `QHS/MS` 分别校准。
