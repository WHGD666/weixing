# v1_targeted_review：第一轮重点错误人工审计

状态：延期，暂不参与第一轮基线

本目录保存基于 `EXP001` 原始标签基线的人工审计记录。第一轮提交采用比赛方原始数据和原始标签，本目录暂不参与第一轮对照；后续版本再启用人工审计。审计的目的，是区分“原始标签确有问题”和“模型在正确标签上的识别失败”，不能把内部评估中的 FP/FN 直接当作标注错误。

## 审计范围

- 数据源：`shiyan/data/`，原始数据只读。
- 原始标签版本：`v0_original`。
- 固定划分：`v1_scene_80_20`，本轮只复核验证清单中的问题图。
- 错误来源：
  `runs/test/exp001_baseline_val_direct_conf030_nms060_20260829/error_analysis/`。
- 预留样本：错误数排序前 30 张图，后续启用审计时人工复核上限为 30 张，不继续无限扩展。
- 重点问题：FSC 重复框与漏检、MS/QHS 舰船框和类别问题、A5_F-16/A13_F-15 细分类混淆。

## 每张图的审计顺序

1. 打开原始图像，先确认目标是否真实存在、是否可辨认。
2. 对照原始 `.txt` 标签检查框的位置、大小、类别和目标数量。
3. 对照错误可视化检查绿色匹配框、橙色误检框和红色漏检框。
4. 对每一个可疑目标填写 `review_queue.csv`。一张图有多个问题时，使用同一行汇总，多个值用英文分号 `;` 分隔，并在 `review_notes` 中逐项说明。
5. 不确定时标记为 `ambiguous`，不要凭模型预测强行改标签。

## 判定标签

`issue_type` 使用以下值之一：

- `model_error`：原始标签合理，属于模型误检、漏检、重复框或细分类混淆。
- `missing_annotation`：图中存在明确目标，但原始标签缺失。
- `wrong_class`：框覆盖目标，但类别明显错误。
- `wrong_box`：类别基本正确，但框明显偏移、过大、过小或截断目标。
- `duplicate_annotation`：同一目标被原始标签重复标注。
- `ambiguous`：分辨率、遮挡或目标形态不足以可靠判断。
- `no_issue`：检查后未发现标签问题。

`proposed_action` 使用以下值之一：

- `keep_original`
- `add_object`
- `change_class`
- `adjust_box`
- `remove_duplicate`
- `defer_review`

`review_status` 使用以下值之一：

- `pending`：尚未开始；
- `in_review`：正在查看；
- `done`：已完成并作出结论；
- `defer`：信息不足，暂缓决定。

## 后续启用时的审计结束条件

本轮 30 张图全部填写后停止人工审计，统计：

- 确认存在标签问题的图片数和目标数；
- 各类问题数量；
- FSC、MS、QHS、A5_F-16、A13_F-15 的问题分布；
- 仍无法判断的样本数。

决策规则：

1. 若确认问题集中且可明确修正，则复制原始标签生成 `v1_audited`，保留修改清单，并只进行一轮 `EXP002` 对照训练。
2. 若大多数是 `model_error` 或 `ambiguous`，不修改标签，直接保留 `v0_original` 作为提交候选。
3. 无论是否修标，原始 `v0_original` 和原始数据都不能覆盖；提交前必须完成一次本地 Docker 接口验证。

## 文件说明

- `review_queue.csv`：本轮 30 张问题图的审计队列和人工填写表。
- `../v0_original/`：原始数据的机器审计结果，只读参考。
- `../../label_versions/v1_audited/`：预留给确认后的修订标签版本，目前不代表已经完成修标。

## 记录要求

人工审计完成后，需要补充一份阶段总结，至少包含审计人、日期、实际修改项、原始标签与新标签的差异、审计结论和是否进入 `EXP002`。没有审计总结，就不能把新标签版本用于训练或报告。
